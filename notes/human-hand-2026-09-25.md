### 왜 게이트가 놓쳤나 — 검사기가 아니라 표본이 문제
`daily_post.clip_survives_inspection()`은 **프레임 2장만** 봅니다: `dur*0.5`(중간), `dur-0.6`(끝).
8초 클립이면 4.0초와 7.4초. 팔은 1.5~2.3초에 들어왔다 나가므로 **두 표본 사이에서 시작해 사이에서 끝납니다.**

실제 API로 확인(2026-10-01):
```
2.17초 프레임 → ok=False :: "a person's arm and hand on the right side"   ← 잡는다
4.00초 프레임 → 사람 언급 없음                                            ← 게이트가 본 프레임
```
`_CHECK_PROMPT` 8번 항목("ANY PERSON … a hand, an arm")은 이미 있습니다.
**검사기는 멀쩡했고, 틀린 프레임을 보여줬을 뿐입니다.**

### 측정으로 프레임을 고를 수 있다
클립을 통째로 6fps·64×114 그레이로 디코드 → 시간축 중앙값을 배경으로 삼고,
**평소 가만히 있는 픽셀**(전체 프레임의 25% 미만에서만 변하는 픽셀)이 바뀐 비율을 점수로:

```
문제 클립(예레미야)   최고 3.65% @2.17s  중앙값 0.00  → 364배   ← 팔이 들어온 바로 그 순간
정상 신명기 8:10      최고 1.40% @6.50s  중앙값 0.75  →   1.9배
정상 요엘 2:21        최고 3.58% @9.00s  중앙값 1.77  →   2.0배
정상 전도서 3:13      최고 4.24% @14.17s 중앙값 0.45  →   9.5배
```
물결·구름은 **늘 변하는 픽셀**에서 움직이므로 점수가 낮고, 침입자는 **평소 조용한 자리**에 나타납니다.
→ 측정이 볼 프레임을 고르고, 모델이 판단한다.

(주의: 위 숫자는 완성된 릴로 쟀고 페이드가 섞이면 오염됩니다 — 고린도후서 9:15는 페이드 때문에 87%가 나왔습니다.

## 고친 것 (2026-10-01, 커밋 예정)

`make_video.intrusion_times(clip)` — 클립 전체를 6fps·64×114 그레이로 훑어
**평소 조용한 픽셀이 바뀐 비율**을 프레임마다 점수로 매기고, 높은 순간 최대 2곳을 돌려줍니다.
`daily_post.clip_survives_inspection()`이 그 순간들을 중간·끝과 함께 같은 비전 게이트에 보냅니다.

실제 문제 클립에 돌린 결과:
```
structure drift: 4.4 (한계 20.0)          ← 드리프트로는 절대 못 잡는다
something enters at 2.1s (novelty 2.91%)  ← 팔
something enters at 7.6s (novelty 0.64%)  ← 접시 든 손
검사 프레임: middle, end, enter1, enter2   (전 2장 → 4장)
```

**수치만으로 반려하지 않습니다.** 팔 클립 최고 3.65 vs 정상 클립 3.58 — 겹칩니다.
겹치는 수치는 어디를 볼지 고를 수는 있어도 게시를 죽일 수는 없습니다.
매 게시 최고점은 `metrics.json`의 `clip_novelty`로 쌓여서, 나중에 모집단이 생기면
그때 반려 여부를 정할 수 있습니다.
