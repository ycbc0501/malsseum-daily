## 1. 붕괴 폭이 부풀려져 있었다 — 그리고 미약한 반등이 이미 있다

**먼저 정정한다.** 이 문서를 쓰기 시작할 때 읽은 숫자는 틀린 숫자였다. §2b 의 버그 때문에
최근 게시물은 **게시 다음 날 숫자에서 얼어붙어** 있었고, 붕괴 전 게시물은 한참 뒤에
백필되어 충분히 익은 숫자였다. **최근을 낮게, 과거를 높게 읽는 편향**이다.

오늘 원장을 풀어주자 48건이 갱신됐다. 몇 개만:

```
09-08 전도서 4:6        1 → 10
09-11 이사야 14:7       2 →  8
09-12 요한복음 6:20     2 →  9
09-01 마태복음 11:28    2 →  9
```

주 단위 평균(좋아요+댓글), **정정 후**:

```
W32  n=15  14.2
W33  n=15  17.2
W34  n=15  22.3     ← 붕괴 직전 주
W35  n=13  12.8     ← 08-27 절벽
W36  n=14   7.2     ← 바닥
W37  n=12   9.2     ← +28%
W38  n= 1   6.0     (오늘 게시 1건, 아직 안 익음)
```

두 가지가 달라진다:

1. **절벽은 여전히 실재한다** — 22.3 → 12.8 → 7.2. 붕괴 자체는 정정 후에도 남는다.
   다만 "15 → 1" 이 아니라 **"22 → 7"** 이다. 1/15 이 아니라 1/3.
2. **W36 → W37 에서 처음으로 올라왔다** (7.2 → 9.2, +28%). 그리고 이 비교는
   회복에 **불리한** 쪽으로 편향돼 있다 — W37 게시물이 W36 보다 **덜 익었는데도** 더 높다.
   둘 다 오늘 같이 갱신됐으므로 측정 시점은 동일하다.

> 판정: **"반등이 전혀 없다"는 내 첫 판단은 틀렸다.** 미약하지만 방향은 위다.
> 그렇다고 기다림이 정답이라는 뜻은 아니다 — 3주 만에 22 의 40% 지점이고,
> 이 속도면 원래 수준 복귀까지 한참이다. 아래 수단은 그대로 유효하다.

팔로워는 08-06 186명 → 09-14 198명 (+12). 죽지는 않았고, 늘지도 않는다.

### 2c. views 의 진짜 차단 사유가 로그에 찍혔다

```
insights tier reach..(9) rejected: HTTP 400:
  (#10) Application does not have permission for this action (code=10)
```

토큰이 아니라 **앱에 권한이 없다.** `IG_ACCESS_TOKEN`(페이스북 로그인 시스템 유저 토큰)은
`instagram_manage_insights` 를 못 받는다 — 비즈니스 관리자에서 SMS 2FA 를 통과해야 하는데
그 번호로 메타 코드가 안 온다. 그래서 `ig_login.py` 가 존재한다: **인스타그램 로그인**으로
읽기 전용 토큰을 따로 발급받는 우회로다.

**`IG_INSIGHTS_TOKEN` 시크릿은 아직 비어 있다. 그것이 채워지기 전에는 조회수를 영영
기록할 수 없다.** 코드는 전부 준비됐고, 남은 건 발급 한 번이다:

```
export IG_APP_ID=... IG_APP_SECRET=...     # Meta 앱 → Instagram → API setup
python3 ig_login.py --auth-url             # 뜬 URL 로 로그인·승인
python3 ig_login.py --code 'AQB...'        # 리다이렉트의 code= 붙여넣기 → 60일 토큰
# 나온 토큰을 저장소 시크릿 IG_INSIGHTS_TOKEN 에 넣는다
```

### 왜 — 원장이 역사를 잃고 있었다

| | |

## 2f. 플래그된 10건을 실제로 열어보니 — **전부 이번 주 새 게시물이었다**

계정 상태 → "오리지널 콘텐츠가 아닌 콘텐츠" 목록 화면. 상위 3건:

```
신명기 1:29    8시간 전   (2026-09-14 05:14)
에베소서 4:3   어제       (2026-09-13 10:46)
로마서 8:6     어제       (2026-09-12 19:03)
                          … 모두 보기(10개)
```

**이것이 모든 것을 바꾼다.**

1. **중복 구절 이론으로는 설명되지 않는다.** 이 셋은 각각 **한 번씩만** 나간 구절이다.
   §2e 의 47개 중복 목록에 셋 다 없다.
2. **09-08 의 아카이브는 실패한 게 아니라 다시 채워진 것이다.** 10건을 치웠는데 다시 10건이다.
   **새 게시물이 올라가는 족족 플래그되고 있다.** 아카이브는 러닝머신이다.
3. **소재 재사용이 아니다.** 오늘 게시물의 빌드 로그:
   ```
   veo motion attempt 1/2/3 … reel(veo native, 2 segment(s)): 신명기 1:29
   ```
   이미지는 Higgsfield 생성, 모션은 Veo 생성, 음악은 Lyria 생성. **100% 우리가 만든 것이고
   8시간 전에 세상에 처음 나왔다.** 픽셀 한 장도 재사용하지 않았다.

### 남는 후보는 텍스트다

우리 게시물의 **글자는 전부 남의 것이거나 고정 템플릿**이다:

| 요소 | 내용 | 고유한가 |
|---|---|---|
| 캡션 | 개역개정 구절 본문 + `[출처]` | ❌ 수천 개 말씀 계정이 같은 문자열을 올린다 |
| 영상 위 글자 | 같은 구절 본문 | ❌ 동일 |
| 첫 댓글 | `FOLLOW_CTA` + 테마별 고정 해시태그 5개 | ❌ 매번 같다 |

**기계 입장에서 이 계정의 텍스트 중 우리 것은 한 글자도 없다.** 규칙 B-5 "캡션은 말씀과
출처뿐"은 지금 인스타그램의 오리지널리티 요건과 **정면으로 충돌한다.**

두 번째 후보: 우리는 **@dailymayim 의 미감을 의도적으로 참조**했다고 `CONTENT_RULE.md`
(19·41·59·329행)에 적어 두었다. 같은 구절 + 비슷한 레이아웃·톤이면 시각 유사도 매칭이
성립할 수 있다. 우리가 문서로 남긴 의도라 부인하기 어렵다.

> **둘 다 가설이다.** 확정하려면 "모두 보기(10개)" 전체 목록이 필요하다 —
> 10건이 **전부 최근 게시물**인지, 아니면 옛 중복이 섞여 있는지가 갈림길이다.
> 이 문서를 이어받는 사람은 그 목록부터 확인할 것.

## 2g. 제재의 범위 — 딱 하나, 그런데 그 하나가 전부다 (09-14 확인)

계정 상태 → **도달** 화면:

| 항목 | 상태 | 내용 |
|---|---|---|
| **회원님을 팔로우하지 않는 사람** | ❗ | **탐색 탭, 릴스, 피드** 같은 위치에 계정과 콘텐츠가 추천되지 않음 |
| 만 19세 미만 | ✅ | 정상 |

두 가지를 확정한다:

1. **위반은 하나뿐이다.** 연령 적합성은 깨끗하다. 콘텐츠가 부적절해서가 아니라
   **오리지널리티 하나** 때문이다.
2. **막힌 것이 유입구 전부다.** 탐색·릴스·피드 추천은 §3-D 표에서 "릴스 추천" 한 줄로
   적었던 그것이고, 우리에게는 **다른 유입구가 없다.** 즉 이 제재가 풀리기 전까지
   신규 도달은 구조적으로 0 이고, §1 의 미약한 반등은 전부 기존 팔로워 안의 움직임이다.

안내문에 **"문제를 해결하거나 조치를 취하지 않을 수 있습니다"** 라고 적혀 있다 —
가만히 두는 것도 인스타그램이 명시한 선택지다. 다만 그 선택은 **추천 0 을 계속 받는다**는
뜻이다.

## 2h. 결정을 위한 구체안 — 캡션에 우리 글을 넣는 경우

§2f 의 결론은 "이 계정의 텍스트 중 우리 것이 한 글자도 없다" 였다. 규칙 B-5 개정은 계정
주인의 결정 사항이므로, **결정이 추상적이지 않도록 실물을 적어 둔다.**

### 지금 (모든 게시물)

```
내가 너희에게 말하기를 그들을 무서워하지 말라 두려워하지 말라
[신명기 1:29]
```

### 제안 — 구절 아래 한 줄, 우리 문장

```
내가 너희에게 말하기를 그들을 무서워하지 말라 두려워하지 말라
[신명기 1:29]

두려움이 사라져서가 아니라, 먼저 가시는 분이 계셔서 건너갑니다.
```

```
평안의 매는 줄로 성령이 하나 되게 하신 것을 힘써 지키라
[에베소서 4:3]

하나 됨은 만드는 것이 아니라, 이미 주신 것을 지키는 일입니다.
```

```
육신의 생각은 사망이요 영의 생각은 생명과 평안이니라
[로마서 8:6]

무엇을 생각하며 하루를 보내는지가, 그 하루가 어디로 가는지를 정합니다.
```

**지키는 것:** 말씀이 먼저고 가장 위다. 파는 말이 아니다. 한 줄이라 "더 보기" 뒤로
접혀도 손해가 없다 — B-5 를 만든 2026-08-01 의 근거(캡션은 ~125자에서 잘린다)와 충돌하지
않는다. 오히려 그 근거는 **CTA 를 넣지 말라**는 것이었지 우리 글을 넣지 말라는 것이 아니었다.

**바뀌는 것:** 게시물마다 세상에 하나뿐인 문장이 생긴다. 기계가 다른 계정과 매칭할 수 없는
텍스트가 처음으로 존재하게 된다.

**구현:** `GEMINI_API_KEY` 는 이미 있다(이미지 파이프라인이 쓴다). `build_caption()` 한 곳만
바뀌고, 생성 실패 시 지금 형태로 조용히 폴백하면 된다. **결정 전까지 코드는 건드리지 않았다.**

### 대안 B — 영상에 브랜드 마크

Saint Seoul 마크를 프레임 구석에 넣는다. 메타 가이드라인이 금지하는 것은 **남의**
워터마크이고, 자기 브랜딩은 오히려 권장된다. 텍스트는 그대로 두고 시각적 구별만 만든다.
효과는 캡션보다 약할 가능성이 높다 — 매칭이 텍스트에서 일어난다는 것이 §2f 의 추정이므로.

### 대안 C — 아무것도 안 하고 검토 요청만

인스타그램이 명시한 선택지이고 비용이 0 이다. 다만 §2f 가 맞다면 **내일 게시물도 플래그된다.**

## 3. 기다림 말고 실제로 있는 수단

증거의 강도 순으로 적는다. **한 번에 하나씩** 바꿔야 무엇이 효과였는지 알 수 있다.

### A. 계정 상태를 직접 확인한다 — 30초, 사람만 할 수 있다 (최우선)

인스타 앱 → 설정 → **계정 상태(Account Status)**.

- 여전히 "추천에서 제외됨 / 퍼온 콘텐츠" 라고 떠 있으면 → **제재가 안 풀린 것**이고,
  거기서 **검토 요청(Request Review)** 을 누를 수 있다. 이건 기다림이 아니라 행동이다.
- 아무 표시도 없으면 → 제재는 풀렸는데 숫자가 안 돌아온 것이고, 원인은 다른 데 있다.

**이 한 번의 확인이 아래 전부의 전제를 가른다.** 우리 쪽 API 로는 이 상태를 못 읽는다.

### B. 플래그된 게시물은 보관이 아니라 삭제

09-08 에 10건을 **아카이브**했다. 아카이브는 프로필에서 숨길 뿐 게시물은 남는다.
중복 게시물이 제재 근거였다면 **남아 있는 한 근거도 남아 있다.** 삭제가 맞다.

### C. 게시 빈도 — 하루 2회는 197명짜리 계정에 과하다

붕괴 전에도 주 13~15건이었으니 빈도가 **원인은 아니다.** 다만 도달이 눌린 상태에서는
같은 관객을 두 번 나눠 먹어 **게시물당 반응률**이 더 떨어지고, 반응률은 추천 알고리즘이
보는 신호다. 2주간 **하루 1회(저녁)** 로 줄이고 게시물당 조회수를 비교해볼 값어치가 있다.

### D. 유입구가 추천 하나뿐이다 — 이게 구조적 문제

현재 이 계정이 새 사람에게 닿는 경로:

| 경로 | 상태 |
|---|---|
| 릴스 추천 | **제재로 막힘** |
| 해시태그 | 스스로 포기 (`hashtags.py`: "해시태그는 도달을 만들지 않는다" — 5개 고정) |
| 트렌딩 오디오 | 없음 (Lyria 자체 생성 음원 → 오디오 페이지 유입 0) |
| 협업·리믹스·스레드 | 없음 |

**즉 추천이 막히면 유입이 0이 된다.** 제재가 풀리기를 기다리는 것 말고 방법이 없는
구조를 우리가 직접 만들었다. 추천 바깥의 유입구를 **하나라도** 만들어야 한다:

- **스레드(Threads) 교차 게시** — 메타 계열이라 프로필 방문으로 직결되고, 텍스트 말씀은
  스레드 포맷에 그대로 맞는다. 자동화 비용도 가장 낮다.
- 트렌딩 오디오를 쓰는 실험 — 다만 RULES 의 음악 규칙과 충돌하므로 규칙 개정이 먼저다.

### E. 콘텐츠에서 숫자가 말해주는 것 (붕괴 전 132건 기준)

| | |
|---|---|
| 테마 최고 | 감사 20.1 · 평안 18.4 · 은혜 18.3 |
| 테마 최저 | **위로 8.2** (n=13) — 다른 테마의 절반 |
| 포맷 | REELS 17.2 > FEED 9.2 |
| 시간대 | 20~21시 21.9 (n=8) > 19시 17.2 (n=42) > 05시 15.9 (n=38) |

- **위로 테마는 재검토 대상이다.** 표본 13건으로 일관되게 절반이다.
- 20~21시가 19시보다 높지만 n=8 이라 **아직 근거가 약하다.** 조회수가 기록되기 시작하면
  다시 본다.
- 붕괴 *후* 에는 FEED 7.7(n=3) > REELS 4.3(n=31) 로 뒤집힌다. n=3 이라 결론은 못 내지만,
  **릴스만 선택적으로 눌렸다**는 가설과 방향이 맞는다. 퍼온 콘텐츠 제재는 릴스 추천을
  때리는 제재이므로 앞뒤가 맞는다. → **캐러셀/피드 비중을 늘리는 실험**의 근거가 된다.

## 3b. 계정 상태 전체 (09-14) — 제재는 **추천 하나뿐**이다

| 항목 | 상태 |
|---|---|
| 콘텐츠 및 메시지 | ✅ **삭제된 콘텐츠나 메시지가 없음** |
| **도달** | ❗ **도달 제한** |
| 기능 | ✅ 모든 기능 사용 가능 |

판정된 적은 없고, 계정이 위험한 상태도 아니다. **추천 자격 하나만** 잃은 것이고, 그게
하필 이 계정의 유일한 유입 경로였다.
